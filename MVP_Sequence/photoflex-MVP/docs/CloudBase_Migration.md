- CloudBase 环境 `photoflex-d0gh9kyug3b971e6d` 只作开发与验收；尚非生产环境。应用只提供邮箱登录，不提供微信或 Google 登录。
- 登录后首页列出当前账号在 CloudBase `public.projects` 中的项目。新建项目及编辑项目、序列、版本、桌面便笺等操作先落到本机工作缓存，再自动保存项目快照到 CloudBase。页面显示「正在保存到云端」「已保存到云端」「自动重试」或「冲突」，无需手动点同步。
- 重新登录或换浏览器，项目列表和项目内容从 CloudBase 读取，沿用原有项目 ID。云端是项目清单与快照的准绳；旧浏览器中仅有的本地项目不会被自动导入，也不会被删除。按照当前决定，不迁移旧 Supabase 项目或旧本地项目。

- 断网或云端暂不可用时，已写入本地的更改保留并自动重试；页面离开前如有未保存内容会提示。云端修订号不匹配时停止覆盖并显示冲突，不能把「本地已存」误认为「云端已存」。目前没有自动合并两台设备并发修改的能力。
- 项目设置页保留，因为它还负责名称、说明、照片来源和删除；手动备份/恢复及「同步」入口已从日常 UI 移除。仅在无法加载项目的故障页面提供恢复用备份下载。

## 结构与权限

[建表 SQL](../cloudbase/migrations/202609160001_create_projects.sql) 已手动应用于当前开发环境。`public.projects` 使用 CloudBase 身份用户 ID 作 `owner_id`，四条 RLS 策略约束用户只能读写和删除自己的项目；`cloud_revision` 用于写入与删除时的并发保护。Git 合并不会自动执行 SQL、复制数据库记录、认证用户或控制台配置。

前端仅配置公开的环境 ID，不能放入服务端 API Key 或邮件服务凭据。未提交的 `.env.development.local` 中使用：

```text
VITE_CLOUDBASE_ENV_ID=photoflex-d0gh9kyug3b971e6d
```

体验版当前不能添加本地开发来源，因此在已允许的默认测试域名验收；没有升级套餐或添加通配域名。

## 合并与上线边界

合并回 `main` 只合并代码和迁移文件，不会改变当前 CloudBase 环境的数据，也不会把未提交的本地环境变量带过去。若 `main` 继续联调此开发环境，需自行配置环境 ID。正式上线应准备独立 CloudBase 环境、执行 SQL、配置正式域名安全来源，并完成上述权限与故障场景验收。当前体验版是否满足正式域名/配额要求，以届时控制台能力和套餐为准；本次未购买或升级。
